# Agent brief: "asset-lineup" — one Blender file with every asset, new and old, side by side

The creator wants to review and improve the scene's assets one at a time (Claude, the car, the phone first, then the rest) and to **compare the vibe of each asset against the others**. Your job is a straightforward assembly job: build **one Blender file, `lab/asset-lineup/lineup.blend`, that shows all the assets together under the same lighting**, so they can be compared at a glance and each can be worked on individually afterwards. You do not redesign or fix any asset in this task.

## Read first
`lab/BRIEF.md` (project rules: $0, minimal, ask before big downloads, never `pkill` things you did not start); `lab/results/scene-polycount-comparison.md` and `lab/results/realistic-scene-diet.md` (what the assets are, their triangle counts); `lab/scene-realistic-car/SCENE_NOTES.md`, `ASSETS.md`; `lab/scene-lowpoly-car/SCENE_NOTES.md`; `lab/tools/polycount.py`. All source files below are **read-only**: copy from them, never modify, save over or delete them. The creator's Blender windows may have some of them open: you only read the saved files.

## How to build it
- Write an **idempotent script** `lab/asset-lineup/scripts/build_lineup.py` (run headless with `/Applications/Blender.app/Contents/MacOS/Blender -b ... --python ...`) that creates `lineup.blend` from scratch: for each asset, **append** (not link) its objects with their materials and images from the source file (`bpy.data.libraries.load(..., link=False)`), put each asset in its own collection (`LU_NEW_Claude`, `LU_NEW_Car`, `LU_NEW_Phone`, `LU_NEW_ParkedCar`, `LU_OLD_Claude`, `LU_OLD_Car`, `LU_OLD_Phone`, `LU_NEW_Human`, ...), keep original object names plus a `LU_` prefix (the originals' names clash across scenes), store `lineup_source` (source file, original object name, git commit of that source file if known) and triangle counts as custom properties on each asset's root, and keep rigs/parents/constraints/drivers working (check that Claude's parts, the car wheels and the human armature still move as one; fix constraints that referenced objects outside the asset or note what was left out, e.g. the car's Follow Path constraint is not needed: remove it in the lineup).
- **Layout:** a clean studio floor with one neutral plinth per asset (simple low-poly discs/boxes, plus text labels with the asset name, source scene and triangle count). Row NEW at the back, row OLD in front, spaced so nothing overlaps; the human to the side. Do not make anything fancy: neutral floor, clear labels.
- **Lighting and render look:** two presets switched by a custom property or a script: (1) **neutral studio** (soft key, fill, rim, neutral grey backdrop) and (2) **scene golden hour** (the sun/sky settings of the realistic scene: reuse its HDRI/sky and colour transform, AgX or whatever the scene uses). Eevee Next with the settings of the realistic scene (1K textures, 256 MB shadow pool, ray tracing as in the scene); draft 960x540 and 1920x1080 presets. 8 GB Mac: render headless, one Blender at a time, keep it light.
- **Cameras:** `LU_CAM_Overview` (everything in frame, 16:9), `LU_CAM_NEW_Row`, `LU_CAM_OLD_Row`, and per asset a front and a 3/4 camera (`LU_CAM_<Asset>_Front`, `_34`) with real-scale framing, plus `LU_CAM_Compare_Claude` and `LU_CAM_Compare_Car` that frame new and old of the same asset next to each other. A tiny `render_lineup.py` renders any camera/preset headlessly: `-- --camera NAME --preset draft|final --light studio|golden --out file.png`.
- **Refresh script:** `scripts/refresh_human.py` re-appends the human from the selection lab's saved file (so the creator can refresh it after the selection agent changes the character) without touching anything else in the lineup.
- Add `.gitignore` rules for `lab/asset-lineup/lineup.blend`, `*.blend1`, snapshots (`lab/asset-lineup/snapshots/`), previews, backups if missing. `.blend` files and snapshots stay out of git; scripts, notes and small stills are committed on your branch.

## Checks and deliverables
1. Render and **look at** (Read the PNGs yourself): the overview in both lighting presets, the NEW row, the OLD row, the Claude comparison and the car comparison, the enlarged phone, the human. Fix layout problems (overlaps, floating objects, wrong scale, missing textures/materials, black/pink materials, broken rigs, labels unreadable).
2. A per-asset table: triangles (use the `lab/tools/polycount.py` method, or equivalent on the lineup collections), object count, texture sizes, source file/object, scale (bounding-box dimensions in metres).
3. Render time and peak memory of one draft overview render (`/usr/bin/time -l`).
4. Open the finished file in a Blender GUI for the creator at the end (`/Applications/Blender.app/Contents/MacOS/Blender lab/asset-lineup/lineup.blend`, in the background of your session, as the creator's window; never kill it; ask before closing). If a creator-opened Blender window is already open on another file, do not touch it.
5. Write `lab/results/asset-lineup.md`: how to open, rebuild, switch lighting, render a camera and refresh the human; the table; honest observations about each asset's look when seen side by side (what vibe each has, what clashes: style, scale, colours, level of detail), what you could not verify; **no redesign suggestions beyond a short factual list of visible problems per asset** (the creator will review Claude, the car and the phone next, in that order). Commit on your branch (commit messages follow `docs/GIT_RULES.md`), copy the final `lineup.blend` to `lab/asset-lineup/lineup.blend` if the harness allows (otherwise give the exact path), and then tell the creator which file to open and stop.
